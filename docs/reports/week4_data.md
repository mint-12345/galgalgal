## 3. 리셋 임계값 비교

train·val·test 센서를 합쳐(2,829장) 스테이지별 시작 시각 순으로 정렬한 뒤, 시작값이 직전 웨이퍼보다 `frac × (스테이지 내 변수 범위)` 이상 줄면 리셋으로 셌다. 라벨은 쓰지 않는다.

| 변수 | 10% (A/B) | 20% (A/B) | 30% (A/B) |
|---|---|---|---|
| BACKING_FILM | 5 / 5 | 5 / 5 | 5 / 5 |
| DRESSER | 3 / 3 | 3 / 3 | 3 / 3 |
| MEMBRANE | 5 / 5 | 5 / 5 | 5 / 5 |
| PSHEET | 5 / 5 | 5 / 5 | 5 / 5 |
| DRESSER_TABLE | 0 / 0 | 0 / 0 | 0 / 0 |
| **POLISH_TABLE** | **102 / 94** | **100 / 87** | **94 / 83** |

**추천: 20%.** 단, POLISH_TABLE은 따로 정해야 한다.

- POLISH_TABLE을 뺀 5개는 임계값이 사실상 무의미하다. 감소가 일어날 때 폭이 변수 범위의 95~100%라 10%든 30%든 같은 결과가 나온다.
- POLISH_TABLE만 민감하고, 감소 폭이 연속적으로 퍼져 있어 자연스러운 경계가 없다 (0~10% 16건, 10~30% 19건, 30~60% 42건, 60~100% 135건). 임계값을 5%→60%로 올리면 합계가 206→136으로 계속 줄기만 하고 평평해지는 구간이 없다.
- 20%를 고른 이유는 CLAUDE.md 5.5절 사전 확인치와 같은 기준이어서 과거 수치와 비교하기 쉽기 때문이다.

### 3.1 POLISH_TABLE 리셋의 해석 (2026-09-27 갱신)

위 횟수는 그대로다. **해석을 고친다: POLISH_TABLE 리셋은 실제 테이블 교체로 판단한다.**
근거 파일 `results/diagnostics/2026-09-27_김혜연_polish_table_reset.csv` (+ `.yaml`),
스크립트 `src/polish_table_reset.py`, 그림 `docs/reports/figs/김혜연_polish_table_stage_A.png`.

- **리셋 직전 최고값**: 중앙값 307~310, 최대 **353~357**. **웨이퍼당 증가량**: 중앙값 **11.1**.
  둘 다 Deivendran 2025(교체 기준 약 350, 웨이퍼당 9~11)와 일치한다.
- 카운터는 **스테이지마다 하나**이고 A-456과 A-123이 공유한다 (같은 시각 값 차이 중앙값 0, 98.5%가 1 이내).
  챔버군으로 쪼개 세면 같은 교체를 두 번 세어 A가 100 → 140회로 늘어난다.

**데이터에는 장비가 처리한 웨이퍼의 약 절반만 기록돼 있다.** 그래서 교체 간격이 짧아 보인다.

| 값 | 스테이지 A | 스테이지 B |
|---|---|---|
| 기간 전체 카운터 증가분 | 24,853 | 22,120 |
| 그중 웨이퍼 기록 안에서 생긴 몫 | 11,983 (**48.2%**) | 11,454 (**51.8%**) |
| 기록 사이 빈칸의 증가 (중앙값) | 16.3 (빈 시간 2,698초) | 20.0 (3,131초) |
| 증가율: 우리 웨이퍼 연마 중 / 빈칸 | 0.025 / 0.005 per s | 0.030 / 0.006 per s |

빈칸의 증가율이 연마 중의 약 1/5이므로 빈 시간의 약 20%가 다른 웨이퍼 연마에 쓰였다는 뜻이다
(2,698초 × 20% ≈ 540초 ≈ 웨이퍼 1.6장). 관측값은 다음 식으로 재현된다.

```
리셋 사이 기록 웨이퍼 수 = 한 주기 증가분 × 기록 안 몫 ÷ 웨이퍼당 증가량
  A: 247 × 0.482 ÷ 7.24 = 16.4   (관측 16.6)
  B: 249 × 0.518 ÷ 9.77 = 13.2   (관측 13.5)
```

Deivendran의 35장은 `350 ÷ 10`으로 한 주기가 0→350이고 모든 웨이퍼가 데이터에 있다고 가정한 값이다.
우리 수치(약 15장)는 **우리 데이터 안에서** 맞고, 35장은 **장비가 실제로 처리한 웨이퍼 기준으로** 맞다. 모순이 아니다.

두 가지를 더 확인했다.

- **웨이퍼 시작값 기준은 리셋의 약 10%를 놓친다.** 센서 행 단위로 세면 A 111 / B 100인데
  시작값 비교로는 A 100 / B 87이다. 두 기록 사이에 리셋이 나고 값이 다시 올라오면 보이지 않는다.
- **A-123 웨이퍼의 55.3%(508장 중 281장)는 웨이퍼 내 카운터 증가가 정확히 0이다** (456 그룹은 0장).
  카운터가 스테이지 공유값이라, 그 웨이퍼의 `start_/delta_/since_POLISH_TABLE_w`는 자기가 쓴 테이블의
  마모가 아니라 **옆 챔버군 테이블의 상태**일 수 있다. A-123의 소모품 상태 입력은 따로 정해야 한다.
> 정정(2026-10-29): 이 결론은 10/28 카운터 진단(PR #14)으로 철회됨. 55% 증가 0은 센서 기록 누락 웨이퍼에서 카운터도 함께 멈춘 결과이며, 카운터는 장비 전체가 공유함.

### 5.2 불러오기

```python
import pandas as pd

T = pd.read_csv("data/processed/wafer_table.csv")

train = T[(T.split == "train") & (T.is_outlier == 0)]   # 1,977장
g456a = train[train.group == "A-456"]                    # 그룹별 모델
X = g456a.filter(regex=r"_(s1|s2)$")                     # R 피처 104개
y = g456a["MRR"]
```

- **test 행의 `MRR`은 비어 있다.** 이게 정상이다. 채우려 하지 말 것.
- 그룹은 `A-456`, `B-456`, `A-123` 문자열이다 (논문별 번호는 CLAUDE.md 11절).
- 컬럼 이름 규칙은 `{통계}_{변수 약어}_{구간}`이다. 예: `mean_RETAINER_s1`, `auc_SLURRY_C_s2`, `slope_POLISH_TABLE_s2`. 구간 `s1`은 첫 챔버(4 또는 1), `s2`는 나머지 두 챔버, `w`는 웨이퍼 전체(S3 전용).
- 전체 컬럼 설명은 `data/processed/COLUMNS.md`.

### 5.3 물리 담당(B·C안, P·V 확정)이 바로 쓸 것

- 압력 6개의 구간별 `mean_*`, `std_*`, `auc_*`와 회전 3개의 `mean_*`가 이미 있다. 8절 P 후보는 집계표만으로 계산된다: P1 = `mean_RETAINER_s1/s2`, P2는 `mean_PCHAMBER_*`(중앙값이 필요하면 원본에서 다시 계산해야 한다), P3 = 에어백 4개 평균.
- **V는 집계표만으로는 부족할 수 있다.** 회전 피처는 구간 평균이라 0인 행이 섞여 있다. 5.4절 경고대로 두 회전이 동시에 켜진 행이 1~3%뿐이므로, V를 정하기 전에 원본에서 챔버별 회전 분포를 봐야 한다.
- 연마 시간은 `dur_POLISH_s1`, `dur_POLISH_s2`다 (단위는 초로 추정).
- S4(P·V 파생)는 아직 만들지 않았다. P·V 대표안이 정해지면 `src/features.py`에 추가한다 (모델 파일 안에서 만들지 않는다, 3절 5번).

### 5.4 재현 조(Di 재현, 게이트 ①)가 바로 쓸 것

- R 피처 ID 22~125(104개)는 모두 들어 있다. **아직 없는 것은 F4인 ID 1~21(MRR 시간 지연 11개, 사용량 이웃 10개)이다.** 이건 7절 규칙대로 `neighbor_features` 함수에서만 계산해야 하므로, 집계표에는 넣지 않았다.
- 이웃 계산에 필요한 입력은 집계표에 다 있다: 같은 그룹 판정(`group`), 시작 시각 순서(`t_start`), 사용량 6개의 z-score 거리 공간(`start_*_w` 또는 구간 `mean_*`).
- 9절대로 **지속 모델(학습 없음)부터 맞춘다.** 지속 모델은 시간 지연 1개만 있으면 되므로 집계표 + `t_start` 정렬로 바로 만들 수 있다.
- Tree bagging은 `RandomForestRegressor(max_features=1.0, random_state=42)`.
- NaN 주의: 불완전 챔버 2장은 `_s2` 피처 52개가 NaN이다. sklearn 회귀에 그대로 넣으면 오류가 나므로 제외하거나 채워야 한다 (추천안은 4절 3번).

### 5.5 주의

- **집계표를 덮어쓰지 않는다.** `src/aggregate.py`는 파일이 이미 있으면 멈춘다. 다시 만들려면 먼저 지워야 하고, 그 전에 왜 다시 만드는지 팀에 공유한다.
- 새 피처는 `src/features.py`에만 추가한다. 모델 파일 안에서 만들지 않는다 (3절 5번).
- 라벨로 계산한 값은 예측 입력이나 샘플링 트리거로 쓰지 않는다 (3절 6번).
