## 1. 물리 파트 (반나절)

목적: **Preston 식의 P(압력)와 V(상대속도)를 이 데이터에서 어떻게 정의할 수 있는지** 확인한다.
결과는 교수님 자문 자료가 된다.

### 1-1. 회전·압력이 언제 켜지는지 보기
```
notebooks/check_rotation.ipynb를 만들어줘. 셀 단위로:
1) 그룹별(A-456, B-456, A-123) 대표 웨이퍼 1장씩 골라서,
   시간축에 회전 3개(wafer, stage, head)를 그리고 챔버 구간을 배경색으로 구분
2) 같은 웨이퍼로 압력 6개도 같은 방식으로
3) 챔버별로 각 회전 변수가 0이 아닌 행의 비율과, 0이 아닐 때의 중앙값을 표로
4) 챔버별로 wafer_rotation과 stage_rotation이 동시에 0이 아닌 행의 비율
그림은 docs/reports/figs/{내이름}_ 로 시작하는 이름으로 저장해줘.
```

**볼 것**: 회전 변수들이 같은 챔버에서 같이 켜지는가, 아니면 따로 켜지는가?
따로 켜진다면 Yu의 정의(스테이지 회전 − 웨이퍼 회전)를 그대로 쓰기 어렵다는 뜻이다.

### 1-2. 압력이 걸리는 챔버 확인
```
원본 센서로 그룹별·챔버별로 RETAINER_RING_PRESSURE와 MAIN_OUTER_AIR_BAG_PRESSURE가
0이 아닌 행의 비율을 표로 만들어줘. 전체-0 센서 웨이퍼를 포함한 값과 제외한 값을 둘 다.
그리고 웨이퍼마다 압력이 가장 많이 걸린 챔버를 세서 그룹별 비율로 보여줘.
결과는 results/diagnostics/{날짜}_{내이름}_pressure_by_chamber.csv (+ yaml)로 저장해줘.
```

**볼 것**: 주 연마가 첫 챔버(4 또는 1)에서 일어나는가? 이게 맞아야 CLAUDE.md 5.3절의 구간 분할이 타당하다.
(김혜연 확인: 456 그룹 99.7~99.8%가 챔버 4, A-123 정상 웨이퍼 90.2%가 챔버 1.
대표 웨이퍼 한 장만 보면 예외 사례를 고를 수 있으니, 반드시 전체 집계로 판단한다.)

### 1-3. P·V 후보 전체 비교표
```
train 행(이상치 제외)으로, 값은 원본 센서에서 계산해서 그룹별로 아래 후보의
변동계수(표준편차/평균)와 MRR과의 상관계수를 표로 만들어줘.

후보:
- 압력 단독 6개: PRESSURIZED_CHAMBER, MAIN_OUTER, CENTER, RETAINER_RING, RIPPLE, EDGE
- 압력 묶음 3개: CLAUDE.md 8절의 P1(리테이너 링), P2(가압 챔버), P3(에어백 4개 평균)
- V 5개: V1(stage−wafer), V2(head−(stage−wafer)), V3(stage), V4(연마 구간 head 평균),
        V5(챔버별로 켜진 회전: 챔버 5는 wafer, 챔버 6은 stage)
- 압력 단독 6개 × V 5개 = 30개 조합
- 비교 기준으로 MRR 자체의 변동계수

계산 방식:
- 각 후보를 (a) 웨이퍼 전체 평균, (b) 압력이 걸린 구간(압력 > 0)만의 평균, 두 가지로 계산
- 전체-0 센서 웨이퍼를 포함한 값과 제외한 값을 둘 다
- MRR과의 상관은 일반 상관과, 웨이퍼 시작 시각·POLISHING_TABLE 사용량의 영향을 뺀
  부분상관(partial correlation)을 둘 다 계산

결과는 results/diagnostics/{날짜}_{내이름}_pv_check.csv (+ yaml)로 저장하고,
상관이 높은 것만 고르지 말고 전체 표를 docs/reports/repro_{내이름}.md 물리 파트에 넣어줘.
CLAUDE.md는 고치지 마.
```

**볼 것**
- **변동계수 비교**: 후보의 변동계수가 MRR보다 훨씬 작으면 그 값은 그룹 안에서 거의 일정하다는 뜻이다. 그런 값은 MRR 차이를 설명할 수 없다.
  (김혜연 확인: V4 head 회전은 0.008~0.035로 MRR 0.091~0.114보다 훨씬 작아 사실상 상수.)
- **곱한 조합 해석 주의**: V1·V3·V5는 회전이 켜졌다 꺼졌다 하는 신호라, 곱한 값의 상관이 높아도 "속도 효과"가 아니라 "켜진 시간" 효과일 수 있다.
  V4는 상수라 곱해도 압력 단독과 거의 같다.
- **최고값만 고르지 않기**: 조합 30개 × 그룹 3개면 상관계수가 90개라, 우연히 높은 값이 섞인다. 판단은 **부분상관**과 **물리적으로 말이 되는지**로 한다.
- **부호 확인**: 웨이퍼를 누르는 압력이 클수록 더 깎여야 하니 양의 상관이 자연스럽다. 음의 상관이 나오면 교수님 자문 질문 2의 근거가 된다.
- **A-123**: MRR 자체 변동계수가 0.026으로 거의 일정해서, 어떤 후보로도 설명할 변동이 적다.

### 1-4. 산점도
```
그룹별로 MRR 대 압력(단독 센서 중 부분상관이 가장 뚜렷한 2개) 산점도를 그려줘.
점 색깔은 웨이퍼 시작 시각으로 칠해줘 (시간 추세가 보이게). train만 사용.
그림은 docs/reports/figs/{내이름}_ 로 시작하는 이름으로 저장해줘.
```

### 물리 파트와 재현 파트는 섞이지 않는다
물리 파트의 결과(P·V 후보, 에어백 평균 등 **우리 제안**)는 교수님 자문과 2막의 B안·C안 준비용이다.
**Di 재현에는 쓰지 않는다.** 재현은 CLAUDE.md 6.1절의 125개(압력 6개를 **각각 따로** 쓰는 Di 방식)만 쓴다.

| | 물리 파트 | 재현 파트 |
|---|---|---|
| 쓰는 것 | P·V 후보 (우리 제안 포함) | Di 125개 피처 (R 세트)만 |
| 결과 위치 | `results/diagnostics/` | `results/` (featureset = R) |
| 코드 | 별도 스크립트 (`src/pv_check.py` 등) | `src/features_repro.py` |

## 2. 재현 파트 (이번 주 핵심)

### 2-1. 이웃 피처 함수 만들기
```

그리고 tests/test_neighbor_{내이름}.py에 다음을 확인하는 테스트도 써줘:
- 시간 이웃이 같은 그룹, 더 이른 시작 시각의 웨이퍼만 쓰는지

### 2-2. 지속 모델부터 (가장 중요)
```

**여기서 막히면 다음으로 넘어가지 말 것.** 학습이 없는 모델이라 숫자가 다르면

## 4. 교수님 자문에 가져갈 것

이번 주 결과가 그대로 자문 자료가 된다. **데이터로는 답이 안 나오고, 공정 지식이나 연구 방향 판단이 필요한 것**만 여쭙는다.
열린 질문("어떻게 할까요?")보다 **근거 + 선택지 + 우리 추천안**을 드리고 고르시게 하는 형식이 효율적이다.

```
질문:   대표 압력으로 무엇을 쓰는 게 물리적으로 타당한가?
근거:   (표 1, 그림 2)
선택지: P1 리테이너 링 / P2 가압 챔버 / P3 에어백 평균
추천:   P2 — 챔버 4에서만 켜지고 MRR과 상관이 가장 높음
```

### ① P·V 정의 (1-1 ~ 1-4 결과) — 최우선
- **질문**: 웨이퍼를 누르는 압력에 가장 가까운 센서는? 이 장비에서 상대속도는 어떻게 구성해야 하나?
- **근거로 가져갈 것**: 회전·압력 트레이스 그림, 챔버별 회전 0이 아닌 비율 표, P·V 후보 비교표
- **왜 필요한가**: 데이터에서 웨이퍼 회전과 스테이지 회전이 **동시에 켜진 행이 1~3%뿐**이라, 논문식 정의(스테이지 − 웨이퍼)를 그대로 쓸 수 있는지 판단이 필요하다.
- **이 답에 따라**: B안·C안이 성립하는지, C안을 정확도 모델로 볼지 해석용 모델로 볼지가 갈린다.

### ② 소모품 사용량의 의미 (week4_data.md의 리셋 분석)
- **질문**: `USAGE_OF_POLISHING_TABLE`이 **웨이퍼 15장마다** 리셋되는데(2,829장 중 187회), 이건 부품 교체인가 정기적인 장비 동작인가? 패드·드레서·멤브레인 중 MRR에 실제로 영향을 주는 건?
- **근거로 가져갈 것**: 변수별 리셋 횟수·간격 표, 리셋 전후 MRR 변화(train·val만)
- **이 답에 따라**: C안의 k 입력(c)에 무엇을 넣을지, 이벤트 트리거를 어떤 소모품으로 잡을지가 정해진다. POLISH_TABLE까지 트리거로 쓰면 계측 예산을 거의 다 써버리는 문제도 같이 상의한다.

### ③ A-123 그룹의 전체 0 센서 웨이퍼 (train 228 / val 40 / test 46)
- **질문**: 센서 고장이나 기록 누락인가, 아니면 그 레시피에서 원래 쓰지 않는 변수인가?
- **근거로 가져갈 것**: 센서별 0 웨이퍼 수, 시간축 분포, 0 센서 웨이퍼와 정상 웨이퍼의 MRR 분포 비교
- **이 답에 따라**: 제외할지, 표시 피처만 추가할지가 정해진다.

### ④ 연구 방향과 주장 수준
- **질문**: 무게중심을 "그레이박스 모델 제안"에서 **"전수 계측 가정의 재검토 + 동일 예산 정책 비교 + k 트리거"**로 옮기는 데 동의하시는지? C안을 "경량화된 PINN"이라 불러도 되는지?
- **근거로 가져갈 것**: 재현 결과(특히 지속 모델 8.78 대 전체 피처 6.48), 선행 연구 대비 차별점 표
- **왜 필요한가**: 선행 연구(Yu 2019, Cai, ISD/ASD, Kang & Kang)에 이미 비슷한 요소가 있어서, 우리 기여를 어디에 둘지 확인이 필요하다.

### ⑤ 평가 설계 (여유 있으면)
- **질문**: test 웨이퍼가 train·val 사이에 시간상 섞여 있는데, 시뮬레이션에서 (가) train+val만 쓸지 (나) 마지막 구간의 test를 13주차에 한 번 공개할지? 계측 비율 10~50%가 현장 기준으로 현실적인가?
- **근거로 가져갈 것**: split별 시간 분포 그림

### 준비 방법
- 본문 2~3쪽 + 그림 부록. 항목마다 위의 네 줄 형식.
- **시점은 5주차 사전 확정 문서(`preregistration.md`)를 커밋하기 전.** 자문 결과가 그 문서에 들어가야 한다.
- 자문 후에는 결정 내용을 `docs/decisions/`에 정리하고, CLAUDE.md·preregistration.md에 반영하는 PR을 올린다.

## 막혔을 때 체크리스트

| 증상 | 확인할 것 |
|---|---|
| 웨이퍼 수가 안 맞음 | 웨이퍼 키를 `(WAFER_ID, STAGE)`로 썼는가? |
| 지속 모델 수치가 다름 | 그룹 안에서 시작 시각 순으로 정렬했는가? 다른 그룹 웨이퍼가 섞였는가? |
| 이웃 피처가 이상함 | 자기 자신을 뺐는가? 미래 웨이퍼를 쓰지 않았는가? |
| 결과가 너무 좋음 | test 라벨이나 미래 정보가 들어가지 않았는지 의심 |
| Claude가 컬럼명을 지어냄 | "실제 파일을 열어서 확인해줘"라고 다시 시킨다 |
| pull/push 충돌 | 공용 파일을 건드리지 않았는지 확인, 카톡에 공유 |
