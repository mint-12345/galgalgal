# SR 최종 식의 그룹 간 상호 적용 — 사후 탐색적 검증 (전준혁, 2026-11-04)

> **성격:** 박종화 정식 SR 결과(`sr/results` 브랜치 `9fa27bd`, 1-표준오차 최종 식)를 확인한 **뒤** 진행한 사후 탐색이다.
> 사전확정 실험이 아니고 test 평가도 아니다. 모든 수치는 train+val의 `folds_v1.csv` 25 fold 평가 RMSE 평균이다.
> PySR은 다시 돌리지 않았고, 식의 형태와 변수는 바꾸지 않았다.
> 코드: `src/sr_cross_group.py`(파싱·재적합·예측·fold는 `src/sr_select.py` 함수 재사용).
> 결과: `results/2026-11-04_전준혁_FV1_sr_cross_group*.csv`, 정의역 점검: `results/diagnostics/2026-11-04_전준혁_sr_cross_group_domain.csv`.

## 식과 처리

| 그룹 | 1-표준오차 최종 식 (척도 적용 변수) | 변수 |
|---|---|---|
| A-456 | `((sqrt(dur)·53.63 + auc_PCHAMBER·auc_MAIN_OUTER·(since_MEMBRANE − 54.23)) / (P1_on·mean_DRESSER_TABLE_s2)) + 74.89` | 6개 |
| B-456 | `(((11.34 − (frac_hi/dur − auc_MAIN_OUTER·frac_hi))^1.806 / auc_SLURRY_C) + frac_hi) / auc_MAIN_OUTER` | 4개 |

공통 변수는 `auc_MAIN_OUTER_s1`, `dur_POLISH_s1` 두 개다(`dur` = `dur_POLISH_s1`).

**척도 처리.** SR 입력은 변수 ÷ (그 그룹 train+val 전체의 절댓값 중앙값)이고, 라벨은 쓰지 않는다(`sr_run.load_frame`). 다른 그룹 식을 적용할 때는 두 가지 척도를 구분했다.
- `source` 척도: 식을 만든 그룹의 중앙값으로 나눈다. 상수의 물리 단위가 원래 식과 같다. ②(계수 고정)의 주 처리다.
- `target` 척도: 적용하는 그룹의 중앙값으로 나눈다. 그 그룹에서 SR을 돌렸을 때와 같은 입력이다. ③(재학습)과 ①의 주 처리다.
- 중앙값이 크게 다른 변수가 있다(`frac_hi` A 0.105 / B 0.048, `P1_on` A 1,865 / B 1,541). 그래서 ②는 척도 선택에 민감하다.

**재학습.** ③은 fold마다 학습 쪽으로만 상수를 다시 맞춘다. `sr_select.refit`을 그대로 썼다(비선형 최소제곱, 초기값 = 상대 식의 PySR 상수, 지수 −3~3).
반복 상한을 200에서 2,000으로 늘려도 결과가 소수 넷째 자리까지 같아서, 수렴 문제는 아니다.

**평가 웨이퍼.** 상대 식 변수는 각 그룹의 SR 사용 웨이퍼(A 940장 / B 951장)에 모두 있다. 그래서 ①②③과 기준선을 **같은 웨이퍼·같은 fold**로 비교했다(`common`).
- 상대 식 변수의 결측(`frac_hi` 7장, `P1_on` 7장, `since_MEMBRANE_w` 28장, `mean_DRESSER_TABLE_s2` 1장)은 모두 원래 SR 사용 웨이퍼 밖이다.
- **① 재현:** 자기 식을 fold별로 재적합한 값이 기존 `FV1_sr_folds.csv`와 fold별로 일치한다(최대 차이 1.5e-8).

|---|---|---|

| ② 상대 식, 계수 고정, source 척도 | 11.393 (0.32) | 8.912 (0.32) |

| **③ 상대 식, 형태·변수 고정, 상수만 재학습 (target 척도)** | **4.722** (0.22) | **5.101** (0.23) |
| ③ 같은 처리, source 척도 (민감도) | 4.716 | 5.142 |

- **보정 t-검정 (탐색적 참고, MSE, ① 대비):** ③은 A·B 모두 ①보다 나쁘다(p < 0.0001). ②와 ②+b도 같다(p < 0.0001).
- **공유 WAFER_ID를 뺀 웨이퍼(A 570 / B 563장)** 에서도 결론은 같다.
  - B→A: ① 4.325 / ② 11.147 / ③ 4.713
  - A→B: ① 4.125 / ② 9.049 / ③ 4.955

**②의 오차는 대부분 수준(절편) 차이다.**

| 방향 | 평균 편향 (예측 − 실제) | 대상 MRR과의 상관 |
|---|---|---|
| B→A | +10.3 (source 척도) / +7.4 (target 척도) | 0.67 |
| A→B | −7.0 / −6.8 | 0.80 |

- 두 그룹의 MRR 평균은 73.5 대 80.3으로 약 6.8 차이 나고, 편향이 이 차이와 비슷하다.
- 자기 식의 상관은 0.74(A) / 0.89(B)다. 단, 이 값은 표본 내 상수로 계산했다.
- 절편 하나만 맞춰도(②+b) RMSE가 11.4에서 4.9로, 8.9에서 5.5로 줄어 ③에 가까워진다.

## 해석 (신중하게)

1. **식 구조가 다르다는 것만으로 "공통 관계식이 없다"고 할 수 없다.**
   - 상대 식을 상수만 다시 맞추면(③) 평균 예측(6.30 / 9.03)보다 크게 낫다(4.72 / 5.10).
   - 자기 식과의 차이는 RMSE 0.48(A) / 0.92(B)다.
   - 계수를 그대로 쓴 ②의 실패도 주로 그룹 간 MRR 수준 차이 때문이고, 순위·변동 패턴은 상당 부분 맞는다(상관 0.67 / 0.80).
2. **그렇다고 공통 식이 있다는 근거도 아니다.**
   - ③은 A·B 모두 자기 식보다 유의하게 나쁘다.
   - ③은 상대 식 변수의 단순 선형회귀(4.71 / 5.00)와 비슷하거나 그보다 나쁘다. 즉 **상대 식의 비선형 형태가 대상 그룹에서 선형보다 나은 정보를 주지 못했다.**
   - 자기 식은 같은 변수 선형회귀보다 낫다(4.24 대 4.47, 4.18 대 4.82).
3. **①과 ③의 차이에는 선택 낙관성이 섞여 있다.**
   - ①의 식은 이 fold 오차로 약 140개 파레토 식 중에서 골랐다. ③의 형태는 대상 그룹 데이터를 보지 않고 정해졌다.
   - 그래서 ①−③ 차이(0.5~0.9)는 실제 구조 차이를 **과대평가**한다. 크기는 이 분석으로 나눌 수 없고, 중첩 교차검증이나 test가 필요하다.
4. **가능한 해석:**
   - 두 그룹은 헤드 압력(`auc_MAIN_OUTER_s1`)과 연마 시간(`dur_POLISH_s1`)이라는 공통 재료를 쓴다.
   - 하지만 수준(절편)과 계수가 그룹마다 다르다.
   - 정확한 함수 형태는 데이터로 하나로 정해지지 않는 것으로 보인다. 파레토에 비슷한 오차의 식이 많고, 상대 식이 선형 수준의 성능을 낸다.
   - "공통 형태 + 그룹별 계수" 가설을 확인하려면 두 그룹을 함께 넣는 SR(그룹별 절편·계수 허용)을 사전에 정해 돌려야 한다. 이번 분석으로 판정할 수는 없다.

## 점검

- **정의역:** 두 식 모두 대상 그룹에서 `sqrt` 음수, `log` 0 이하, 0으로 나누기, 음수 밑의 비정수 거듭제곱이 **한 건도 없었다.**
  - 이는 고정 상수와 fold별 재적합 상수에 모두 해당한다.
  - B 식의 거듭제곱 밑 최솟값은 5.87이고, A 식의 분모 최솟값은 0.47이다. 계산 불가 웨이퍼는 0장이다.
- **누수:**
  - fold마다 대상 그룹 안의 학습·평가 쪽 키와 WAFER_ID가 겹치지 않음을 확인했다.
  - A-456과 B-456은 WAFER_ID 405개를 공유하고, 그 쌍의 MRR 상관이 0.57이다. 같은 웨이퍼가 두 스테이지를 거친 것으로 보인다.
  - ②는 상대 그룹 전체로 맞춘 상수를 쓰므로, 공유 웨이퍼를 통해 대상 MRR 정보가 들어갈 수 있다.
    공유 ID를 뺀 결과도 결론이 같아서 이 경로의 영향은 작아 보인다. 공유 ID를 뺐을 때 ②의 RMSE는 B→A에서 11.39 → 11.15, A→B에서 8.91 → 9.05였다.
  - ③은 상대 상수를 초기값으로만 쓰고, 반복 상한을 늘려도 결과가 같다.
- **척도 통계:** 그룹 train+val 전체로 1회 계산했다(사전확정 4.8 1번과 같은 예외, 라벨 미사용).
- **실행 시간:** 전체 17초(PySR 재실행 없음).
- **test 라벨·`data/locked/`:** 쓰지 않았다.
