# Step 2. PHM 2016 training 데이터 기록 구조 확인

- 대상: `data/raw/PHM2016/2016 PHM DATA CHALLENGE CMP DATA SET/` 의 training 공정 파일 185개와 `CMP-training-removalrate.csv`
- test / validation 데이터는 열지 않았습니다.
- 데이터 가공, 저장, feature 생성, 모델링은 하지 않았습니다.
- 확인 코드: `scripts/step2_inspect_training_structure.py`

## 1. 규모

| 항목 | 값 |
|---|---|
| 공정 파일 | 185개 (그중 `CMP-training-066.csv` 는 헤더만 있고 행 0) |
| 공정 데이터 전체 행 | 672,744 |
| 고유 wafer 수 | 1,699 |
| 고유 wafer + Stage 조합 수 | 1,981 |
| MRR 정답 행 수 | 1,981 |

- wafer 1,417개는 Stage 하나만, 282개는 Stage A와 B 둘 다 기록되어 있습니다.
- MACHINE_ID 는 모든 행에서 2 하나뿐입니다.

## 2. Stage / Chamber 값

- Stage: `A`, `B` 두 가지입니다. 조합 수는 A 1,166개, B 815개입니다.
- Chamber: `1, 2, 3, 4, 5, 6` 여섯 가지입니다. 파일에는 `1.0` 처럼 실수로 기록되어 있습니다.
- Stage B 는 Chamber 4~6 에서만 기록됩니다. Stage A 는 1~3 에서 368개, 4~6 에서 798개 조합이 기록됩니다.
- 두 Stage 가 모두 있는 wafer 282개는 A와 B 모두 Chamber 4~6 입니다.

## 3. wafer + Stage 한 묶음의 기록 방식

- **여러 줄로 기록됩니다.** 묶음당 행 수는 최소 182, 중앙값 342, 최대 5,492 입니다. 1줄짜리 묶음은 없습니다.
- **기록 시간은 보통 약 6분입니다.** 중앙값은 359초이고, 행 간격은 대부분 0.3~1.3초로 불규칙합니다.
- **대부분 파일 하나에 들어 있습니다.** 1,956개는 파일 하나, 25개는 번호가 이어진 두 파일에 나뉘어 있습니다.
- **대부분 Chamber 3개를 차례로 거칩니다.** 1→2→3 이 368개, 4→5→6 이 1,609개입니다.

일반적이지 않은 기록도 있습니다.

| 유형 | 내용 |
|---|---|
| Chamber 순서가 다른 묶음 | 4만 거침 2개, 4→6 1개, 5→6→4→5→6 1개 |
| 행 수가 매우 많은 묶음 | 3021014294 B 5,492행, 3015014228 B 5,205행, 4201773386 B 2,202행 |
| 기록 시간이 매우 긴 묶음 | 2921014258 A 는 353행인데 약 29,311초에 걸쳐 있음 |
| 같은 묶음 안 TIMESTAMP 중복 | 670개 묶음, 2,221행. 그중 1,819행은 모든 컬럼이 완전히 같음 |
| 파일 순서상 끊긴 묶음 | 파일을 번호순으로 이어 붙이면 20개 묶음이 두 구간 이상으로 끊김 |

## 4. MRR 정답 연결

- 공정 데이터의 1,981개 조합과 MRR 파일의 1,981개 조합이 정확히 일치합니다.
- MRR 파일에 중복 조합과 결측값이 없습니다.
- 따라서 모든 wafer + Stage 에 MRR 정답이 하나씩 연결됩니다.
